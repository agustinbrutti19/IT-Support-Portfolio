# KB-004 — Shared Drive Access Issues

**Category:** Access / Permissions  
**System:** Shared Drives  
**Audience:** Helpdesk  
**Severity:** Medium  
**Last Updated:** 2026-10-06

## Problem

Users may be unable to access a Shared Drive or specific folders within it.

The issue may prevent users from viewing, opening, creating, editing, or accessing files required for their daily work.

## Symptoms

Common symptoms may include:

- User receives an access denied message.
- Shared Drive is not visible to the user.
- User can see the Shared Drive but cannot open specific folders.
- User can open files but cannot edit them.
- User cannot create or upload files.
- User cannot move or delete files.
- Other users can access the same location normally.
- Access worked previously but is no longer available.

## Troubleshooting Steps

1. Confirm the exact Shared Drive, folder, or file the user is trying to access.
2. Confirm the user's account and department.
3. Determine whether the issue affects one user or multiple users.
4. Verify whether the Shared Drive is visible to the user.
5. Check whether the user can access other Shared Drives or folders.
6. Confirm whether the user can view the affected location but cannot perform specific actions.
7. Verify the user's group membership or assigned access.
8. Check whether the requested permission matches the user's job responsibilities.
9. Confirm that the issue is not caused by an incorrect Microsoft 365 account.
10. Test access again after any approved permission change.
11. Document the results and determine whether the issue is related to permissions, account configuration, or a broader service problem.

## Common Causes

Common causes may include:

- User is not a member of the required access group.
- Incorrect permissions assigned to the user.
- User is signed in with the wrong Microsoft 365 account.
- Access was recently removed or changed.
- User's department or role changed without updating access.
- Folder-level permissions restrict access.
- The Shared Drive or folder has specific restrictions.
- Account is inactive, disabled, or otherwise not authorized.
- Permission changes have not yet propagated.
- The issue is caused by a broader Microsoft 365 or Shared Drive service problem.

## Resolution

The resolution depends on the identified cause.

Possible resolutions include:

- Correcting the user's Microsoft 365 account selection.
- Adding the user to the appropriate access group when authorized.
- Correcting incorrect permissions.
- Restoring access after an approved permission change.
- Updating access when the user's department or role has changed.
- Correcting folder-level permissions when appropriate.
- Waiting for approved permission changes to propagate before retesting.
- Resolving account status issues when permitted by Helpdesk procedures.
- Escalating broader Microsoft 365 or Shared Drive service issues.

After applying the resolution, Helpdesk should verify that the user can access the required location and perform the expected actions.

## When to Escalate

Escalate the ticket when:

- The required permissions are unclear or require approval from another department.
- The issue requires administrator access beyond Helpdesk permissions.
- The user is correctly configured but access continues to fail.
- Multiple users are affected by the same access problem.
- The Shared Drive or Microsoft 365 service may be experiencing a broader issue.
- There is a suspected security or unauthorized access issue.
- The requested access conflicts with company security or access policies.
- The problem persists after standard permission and account troubleshooting.

## Information Required for Escalation

Include the following information when escalating the ticket:

- User name and department.
- Ticket number.
- Shared Drive, folder, or file affected.
- Requested access or action.
- Current access level, if known.
- Expected access level based on the user's role.
- Exact error message.
- Whether the issue affects one user or multiple users.
- Microsoft 365 account used by the user.
- Relevant group membership or permission information.
- Troubleshooting steps performed and their results.
- Recent changes to the user's department, role, or access.
- Screenshots or other relevant evidence.
- Business impact on the user or department.
